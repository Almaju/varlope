Code that a PR's CI never compiles breaks the first build that does: a Kotlin wrapper missing a `return` landed because no PR job built the module (#7437), and Swift wrappers broke after a field rename (#5223). The same holds for the taskgraph: a transform change that is never generated against the release and nightly parameter sets fails the decision task later (#5689). Every PR should build all Kotlin modules with warnings as errors, and generate the graph for `taskcluster/test/params/`.
