When a Kotlin, Swift or JS implementation of a callback throws and the Rust signature has no error type, UniFFI has nowhere to put the exception and panics in Rust; a reviewer made returning `Result` the only blocker on the context_id component. Callbacks kept past `shutdown()` leak the foreign object too: #7520 had to add a shutdown API to ads-client because a registered `MozAdsTelemetry` callback outlived desktop's xpcom-shutdown, and #7478 fixed logins keeping its `PrimaryPasswordAuthenticator` alive after shutdown.
