When a Remote Settings record is deleted, every row ingested from it must go too; rows left behind in a side table outlive their record and can match the wrong suggestion later. Reviewers ask each new Suggest table for a `record_id` (or an `ON DELETE CASCADE` parent) and a `DELETE` in `drop_suggestions()`, and push back on the reverse mistake: a read such as logins' `decrypt_fields` that deletes rows, so a transient failure destroys data.
